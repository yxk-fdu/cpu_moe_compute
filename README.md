## 下载什么

**准备CPU计算后端，下载完整的 [`cpu_moe/`](cpu_moe/) 目录即可。** 不要只取其中的 `kt-kernel/`，它还需要同级依赖与运行时文件。另从 [部署指南及参考脚本](部署指南及参考脚本/) 取使用说明、启动脚本；日志合成工具在独立的 [profile合成指南](profile合成指南/) 中。无需为了准备后端下载其他说明或日志样例。

## 两个仓库的关系

还必须单独准备 [vllm-ascend 的 `moe_cpu_compute_v1-on-0928` 分支](https://github.com/yxk-fdu/vllm-ascend/tree/moe_cpu_compute_v1-on-0928)。**Ascend侧代码与CPU计算后端缺一不可**：前者负责CPU/NPU专家分工、LRC、搬运、预取和同步；本仓库 `cpu_moe/` 负责CPU专家计算。

### 共享 NZ 配对

使用配套的 vLLM 0.30.0、vLLM-Ascend 源码和本仓库源码。为目标架构编译 kt-kernel，确认原生扩展导出 `NZMOE`、派发 ABI 和线程池拓扑预检接口。

加载模型原有的 MXFP4 checkpoint 时，Ascend 生成 NZ 权重和 scale，CPU 后端与 NPU DMA 读取同一批缓冲区。配置 `cpu_moe.enabled=true` 会给所有符合条件的 MoE 层挂上 CPU 后端。计算线程与共享权重使用同一 NUMA 节点。构建和启动流程见 [脚本设定指南](部署指南及参考脚本/脚本设定指南.md)。

模型权重和编译后的运行库另行准备。更新 GitHub 时检查两边源码，有改动的一边同步更新，并记录新的配套版本。


## CPU 专家冷权重微基准（2026-11-12）

本轮测量共享 NZ 权重下 CPU 专家批量计算耗时，比较两种路由，token 数 `N = 1…6`。

- **不同专家（distinct）**。N 个 token 各命中一个不同专家，每个专家处理一个 token。
- **同一专家（shared）**。N 个 token 全命中同一个专家，同批 token 共用一次权重块读取和解包。

### 测试环境与计时口径

| 项目 | 设置 |
| --- | --- |
| 测试机器 | 9334，AMD EPYC 9575F 64-Core Processor，x86_64，双路、每路 64 核、每核 2 线程；109，Kunpeng 950 7592C，2.3 GHz，aarch64 |
| 计算资源 | 两台均绑定 NUMA 1 的 30 个物理核 |
| 模型与专家 | DeepSeek-V4-Flash-0731，第 21 层，专家 ID 127–132 |
| 权重 | 模型 NZ 权重及 scale，单专家驻留数据 13,369,344 字节（12.75 MiB） |
| 冷权重处理 | 每次测量前驱逐选中专家的 NZ 权重缓存，驱逐操作在计时区间之外 |
| 计时范围 | CPU batch forward 入口至整批 BF16 输出完成，每批一个并行区、两次阶段 barrier |
| OpenMP 等待策略 | `OMP_WAIT_POLICY=ACTIVE`、`GOMP_SPINCOUNT=INFINITE` |
| 采样与统计 | 9334 每个 N、每种路由采样 144 次；109 合并两轮，每点 288 次，取耗时中位数拟合 |
| 数值校验 | 对照 x86 参考结果逐位校验，9334 共 1,728 个样本，109 共 3,456 个样本 |

计时覆盖 CPU 专家计算和批内同步。路由、任务排队、NPU 派发、H2D/D2H 及结果返回位于该计时范围之外。这里采用独立 CPU 微基准的测量口径。

9334 的 CPU 型号已从当时的 `lscpu` 输出核对。109 的 CPU 型号由 2026-11-23 的只读 `lscpu` 查询确认。两台机器的完整操作系统、编译器版本和源码 commit 未随该拟合记录完整归档。以下数据对应 2026-11-12 的实验版本。

### 线性拟合

用上述 N=1…6 的中位数拟合 `T(N) = a + b × N`，T 的单位为 μs。

| 机器 | 路由 | 拟合直线 | R² | 斜率含义 |
| --- | --- | --- | ---: | --- |
| 9334 x86 | 不同专家 | `T ≈ 4.7061 + 75.0750 × N` | 0.999770 | 每追加一个 token 并命中新专家，增加约 75.1 μs |
| 9334 x86 | 同一专家 | `T ≈ 60.5421 + 19.3623 × N` | 0.993724 | 同一专家每追加一个 token，增加约 19.4 μs |
| 109 ARM | 不同专家 | `T ≈ 8.4560 + 107.2947 × N` | 0.999906 | 每追加一个 token 并命中新专家，增加约 107.3 μs |
| 109 ARM | 同一专家 | `T ≈ 77.0840 + 35.8453 × N` | 0.995583 | 同一专家每追加一个 token，增加约 35.8 μs |

斜率表示对应路由下的边际耗时。单专家单 token 的实际耗时可直接读取 N=1 行。同一专家的批量计算复用了权重读取与解包，因而追加 token 的边际耗时更低。拟合的测量范围为 N=1…6，截距是该范围内回归得到的参数。

数据来源为当轮归档文件 `cold-expert-linear-fit-109-9334-20261112.json` 的 `hosts` 结果。该文件另含 `GOMP_SPINCOUNT=5000000` 对照，表中采用主实验的无限自旋结果。
